# maket Desktop

Отдельная сборка того же редактора для Windows x64, Linux x64 и macOS (Intel и Apple Silicon). Приложение содержит Electron, Next.js standalone и PostgreSQL 17. Пользователю не нужны сервер, Docker, Node.js и отдельная СУБД. Сетевое подключение при обычной локальной работе не требуется.

Серверная версия использует прежние зависимости, PostgreSQL, Dockerfile и команды запуска. Desktop имеет свой package.json/lockfile, отдельный `.next-desktop` и `.build`; в Docker-контекст desktop не входит. Desktop-сборка восстанавливает изменяемые Next.js файлы типов/настроек после завершения.

## Готовые приложения

Скачивайте файлы из [GitHub Releases](https://github.com/DoshikKing/maket/releases) с тегом `desktop-v…`.

| Платформа           | Установка                                                        | Portable                                                                                       |
| ------------------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| Windows x64         | `maket-…-win-x64.exe`, мастер NSIS, установка без администратора | `maket-…-win-x64-portable.exe`                                                                 |
| Linux x64           | `maket-…-linux-amd64.deb`                                        | `…-portable.AppImage` или `…-portable.tar.gz`; архив распаковать полностью и запустить `maket` |
| macOS Intel         | `maket-…-mac-x64.dmg`, перенести приложение в Applications       | `…-mac-x64-portable.zip`, распаковать и запустить `maket-portable.command`                     |
| macOS Apple Silicon | `maket-…-mac-arm64.dmg`                                          | `…-mac-arm64-portable.zip`, запуск через `maket-portable.command`                              |

Не запускайте portable прямо из архива или образа DMG. Выберите обычную папку с правом записи. macOS-лаунчер сохраняет выбранную папку данных даже при App Translocation.

Сборки не подписаны сертификатом разработчика; Apple notarization не настроена. Windows SmartScreen/macOS Gatekeeper могут запросить подтверждение запуска. Sandbox, изоляция renderer и проверка TLS остаются включены. AppImage требует FUSE; вариант tar.gz его не требует. На Linux с запретом unprivileged user namespaces рекомендуется `.deb` с системным sandbox helper, а не отключение sandbox.

## Данные и обновления

При первом запуске автоматически создаются локальная база, локальный профиль и пустая рабочая область. Регистрация и код приглашения не нужны. Профиль и тему можно менять в настройках. Локальный профиль не является аккаунтом серверной версии.

- Установленная версия: `%APPDATA%/maket-desktop` в Windows, `~/Library/Application Support/maket-desktop` в macOS, `~/.config/maket-desktop` в Linux (либо каталог XDG config).
- Portable: `maket-data` рядом с exe/AppImage/распакованным приложением. Можно перенести всю папку на другой компьютер **той же ОС и архитектуры**, предварительно закрыв приложение. Для переноса между разными ОС используйте экспорт/импорт диаграмм.
- «Файл → Открыть папку данных» показывает точное расположение.
- В `desktop.json` находятся реквизиты локальной базы; храните его вместе с каталогом `postgres`. Потеря файла не приводит к автоматическому сбросу существующей базы.
- Перед обновлением закройте все окна, замените только приложение и оставьте папку данных. Перед запуском миграций при смене версии создаётся холодная резервная копия `postgres` и `desktop.json` в `backups`. Если копирование не удалось, обновление базы не начинается.
- Не открывайте актуальную базу старой программой. Для возврата к старой версии восстановите её резервную копию при закрытом приложении.
- Удаление установщика не удаляет профиль. При ручном удалении `maket-data` удалятся все локальные данные.
- Резервная копия вручную: закройте приложение, убедитесь, что завершилось сохранение, скопируйте всю папку данных. Для восстановления сначала сохраните текущую папку, затем замените её копией. Локальное хранилище не шифруется приложением; используйте защиту диска средствами ОС.

Локальные сервисы слушают только `127.0.0.1`, порт HTTP сохраняется между запусками. Native-окно добавляет отдельный случайный секрет к запросам; без него интерфейс/API не открываются даже в другом браузере. Node.js и системные API недоступны странице. PostgreSQL использует случайный пароль и SCRAM.

## Возможности и MCP

Работают диаграммы, нотации, дерево, связи, наследование, ракурсы/2.5D, история, импорт и экспорт. Локальные области изолированы от серверных; автоматической синхронизации с сервером нет. Для обмена используйте JSON/draw.io.

Публичные ссылки и совместная работа через интернет доступны в серверной версии. В desktop не открываются внешние порты, не создаются туннели и не настраивается маршрутизатор.

MCP доступен клиенту на том же компьютере. Создайте ключ в настройках, скопируйте URL из настроек или меню «Файл → Скопировать адрес MCP» и передайте `Authorization: Bearer <ключ>`. Native-секрет не нужен MCP-клиенту: endpoint самостоятельно проверяет MCP-ключ, функции и области. Приложение должно быть запущено. Для облачной модели нужен MCP-клиент на компьютере, который поддерживает локальные HTTP-серверы; localhost недоступен поставщику модели напрямую.

## Сборка из исходников

Нужен Node.js 24 и обычный пользователь ОС (PostgreSQL не запускается от root). Собирайте на целевой ОС и архитектуре; CI использует отдельный runner для каждой платформы.

```sh
npm ci
npm ci --prefix desktop
npm --prefix desktop run build
npm --prefix desktop run smoke
npm --prefix desktop run pack
npm --prefix desktop start
npm --prefix desktop run dist
```

Результаты — `desktop/dist`. Последняя команда создаёт установщик и portable. Прокси/корневые CA при необходимости настраиваются обычными средствами Node/Electron; проверка сертификатов не отключается. Локальные `.env` удаляются из standalone-пакета; реквизиты серверной базы не наследуются при desktop-запуске.

## Релизы

Workflow `.github/workflows/desktop-release.yml` собирает Windows, Linux, macOS Intel и ARM на нативных runner, проверяет локальный запуск и сохраняемость данных. На Linux дополнительно проверяется окно упакованного Electron. Только после успеха всех платформ создаётся GitHub Release со всеми файлами и `SHA256SUMS`.

Для нового выпуска измените версию в `desktop/package.json`, обновите `desktop/package-lock.json` и `desktop/RELEASE_NOTES.md`, закоммитьте и отправьте тег, совпадающий с версией:

```sh
git tag desktop-v0.1.3
git push origin desktop-v0.1.3
```

Ручной запуск workflow без тега создаёт Actions artifacts и не публикует релиз. Обновления устанавливаются пользователем; автоматического скачивания и замены приложения нет.
