# Документы и нотации

## Файл диаграммы

`.maket.json` содержит `{ "name": "Название", "document": { ... } }`. Импорт также принимает сам документ. Текущий формат диаграммы — **v2**; формат нотаций остаётся **v1**.

```json
{
  "schemaVersion": 2,
  "modelSpaceId": "space-id",
  "bindings": [{ "id": "binding-id", "versionId": null, "document": {} }],
  "objects": [
    {
      "id": "object-id",
      "parentId": null,
      "name": "Заказ",
      "description": "",
      "attributes": { "automated": true },
      "archived": false,
      "revision": 1
    }
  ],
  "nodes": [
    {
      "id": "representation-id",
      "objectId": "object-id",
      "bindingId": "binding-id",
      "typeId": "process",
      "position": { "x": 100, "y": 100 },
      "properties": {},
      "label": "Необязательная локальная подпись"
    }
  ],
  "edges": [
    {
      "id": "edge-id",
      "bindingId": "binding-id",
      "typeId": "flow",
      "source": "representation-id",
      "target": "another-representation-id",
      "sourcePort": "out",
      "targetPort": "in",
      "properties": { "label": "Далее" }
    }
  ]
}
```

Это иллюстрация структуры: `bindings[].document` должен содержать полную валидную нотацию, а оба конца связи — существовать. Рабочий файл получается экспортом из редактора. Исполняемые схемы: `src/lib/model.ts` и `src/lib/notation.ts`.

`objects` содержит снимки используемых объектов и их предков; `nodes` — независимые представления этих объектов. Несколько узлов могут иметь одинаковый `objectId`. `bindingId` фиксирует конкретный снимок нотации; одинаковые `typeId` в разных подключениях независимы. Поясняющая графическая связь использует `bindingId: null`, `typeId: "association"` и может соединять представления разных нотаций. Семантические связи нотации действуют внутри своего подключения.

Импорт через библиотеку принимает v1 и v2. При импорте v2 сервер создаёт новые идентификаторы объектов и подключений, переписывает ссылки и родителей, сохраняет повторные представления одного объекта. Нотации в файле автономны: `versionId` сбрасывается. Встроенный импорт редактора заменяет раскладку только в том же пространстве, с теми же подключениями и существующими объектами; для переноса между пространствами используйте библиотеку.

Ограничения: 2 МБ на запрос/файл, 12 подключений нотаций, 5000 объектов в документе, 1000 представлений, 3000 связей. На нотацию: 50 типов узлов, 20 типов связей, 1000 правил. У объекта: имя до 100 символов, описание до 4000, до 100 атрибутов примитивных типов. Идентификаторы — латинские буквы, цифры, `_` и `-`, до 100 символов. Цвета — `#RRGGBB`, без внешних URL.

Прежний v1 `{schemaVersion:1, notation, nodes, edges}` поддерживается для импорта и исторических снимков. Существующие диаграммы переводятся в v2 при первом обращении к модели/библиотеке; каждому старому узлу соответствует отдельный объект со стабильным идентификатором. Прежняя история сохраняется в исходном виде. Совпадение имён не объединяет объекты.

## Файл нотации

`.notation.json` содержит документ нотации без обёртки. Обязательны:

- `schemaVersion: 1`, `id`, `version` в формате `major.minor.patch`, `name`;
- `nodeTypes`: уникальный `id`, `name`, `appearance`, `properties`, `ports`;
- `edgeTypes`: уникальный `id`, `name`, `appearance`, опциональные `properties`;
- `connectionRules`: `edgeType`, `source: {nodeType,port}`, `target: {nodeType,port}`, `allowSelfLoop`.

`appearance` узла: `shape` (`rectangle`, `rounded`, `diamond`, `ellipse`, `text`, `custom`), `width` (40–600), `height` (30–400), `fill`, `stroke`. Дополнительно: `strokeWidth` (0.5–12), `fontSize` (8–72), `textRotation` (−180…180 градусов), `textAlign` (`left`, `center`, `right`), `showAttributes` (по умолчанию включено). Для `custom` обязателен `shapeId` существующей формы.

Свойство: `key`, `label`, `type` (`string`, `number`, `boolean`), `required`, опциональный `default` соответствующего типа. Поле `title` отображается внутри узла, `label` — на связи. Остальные свойства узла также видны на фигуре; логические значения показаны как «Да»/«Нет». `visible: false` скрывает конкретное свойство на фигуре, сохраняя его в инспекторе. `showAttributes: false` скрывает весь блок атрибутов.

Порт: `id`, `direction` (`input` или `output`), опциональный `maxConnections`. Входы располагаются слева, выходы справа. Правила соединения могут ссылаться только на существующие типы и порты нужного направления.

Внешний вид связи: `line` (`solid`, `dashed`, `dotted`, `dash-dot`, `custom`), `targetMarker`, `color`. Дополнительно: `sourceMarker`, `width` (0.5–12), `markerSize` (8–40), `fontSize` (8–48), `routing` (`smoothstep`, `straight`, `bezier`). Маркеры обоих концов: `none`, `arrow`, `thin-arrow`, `thick-arrow`, `triangle`, `hollow-triangle`, `diamond`, `hollow-diamond`, `circle`. Для `custom` нужен `dashPattern`: 2–8 положительных чисел до 50, чередующих длины штрихов и промежутков в пикселях. Стандартные пунктирные шаблоны масштабируются с толщиной линии.

## Настройки отдельных элементов

Узел диаграммы может содержать `size: {width, height}` (40–2000 × 30–1600), целочисленный `layer` (−1000000…1000000), `label` (до 2000 символов) и `appearance` с переопределениями оформления. Связь также принимает `appearance`. Настройки экземпляра имеют приоритет над настройками типа, размеры — над размерами типа. Больший `layer` располагается выше. Команды перемещения по слоям нормализуют уровни, сохраняя взаимный порядок остальных элементов.

Двойной щелчок редактирует локальный `label` представления. Без локального `label` или `properties.title` строковое свойство `title` наследует имя объекта. Общие свойства редактируются отдельно через дерево или кнопку инспектора. «Сбросить локальную подпись» возвращает наследование общей подписи. Enter сохраняет текст, Shift+Enter добавляет строку, Escape отменяет изменение. Изменение размера доступно через рамку выбранного объекта и поля инспектора.

## Пользовательские формы

Необязательный массив `shapes` в нотации содержит до 50 форм. Пример формы и оформления типа:

```json
{
  "shapes": [
    {
      "id": "slanted-process",
      "name": "Скошенный процесс",
      "baseShape": "rectangle",
      "points": [
        { "x": 15, "y": 0 },
        { "x": 100, "y": 0 },
        { "x": 85, "y": 100 },
        { "x": 0, "y": 100 }
      ],
      "rounding": 8
    }
  ],
  "appearance": {
    "shape": "custom",
    "shapeId": "slanted-process",
    "width": 180,
    "height": 100,
    "fill": "#eef2ff",
    "stroke": "#6366f1"
  }
}
```

Фрагмент нужно разместить в полном документе: `shapes` на верхнем уровне, `appearance` внутри соответствующего `nodeTypes`. `baseShape` — `rectangle`, `rounded`, `diamond` или `ellipse`; `points` — 3–32 точки замкнутого контура с координатами 0–100 процентов; `rounding` — 0–45 процентов. Контур с нулевой площадью отклоняется. Конструктор позволяет менять базу, двигать точки, добавлять/удалять их и скруглять углы. Формы масштабируются с узлом и экспортируются вместе с нотацией. Произвольный SVG, HTML и исполняемый код не принимаются.

Поля оформления необязательны и совместимы с нотациями v1 и прежними файлами диаграмм v1. Прежние документы не получают новые поля при разборе. Новая версия нотации с формами применяется к новым диаграммам; уже созданные диаграммы продолжают использовать сохранённый снимок.

## Версии

- `schemaVersion` — версия файлового формата. Диаграммы сохраняются в v2; v1 поддерживается для импорта и истории. Нотации сохраняют формат v1. Неизвестные версии отклоняются.
- `bindings[].document.version` — версия языка моделирования. При редактировании должна увеличиваться. Все сохранённые версии остаются неизменяемыми.
- `Diagram.revision` — номер снимка диаграммы. Сервер принимает сохранение только при совпадении ожидаемого номера; иначе HTTP 409.

Существующая диаграмма хранит снимок нотации и ссылку на её версию (если создана из библиотеки нотаций). Замена нотации при сохранении запрещена. Импорт создаёт независимую диаграмму со встроенной нотацией. Восстановление создаёт новую ревизию; прежняя история не удаляется. Если неиспользуемая нотация уже удалена из библиотеки, её исторический снимок восстанавливается как автономное подключение с `versionId: null`.

## Область свойств и смена отображения

У свойства типа узла можно указать `scope: "object"` и `objectKey` для привязки к общему атрибуту. Например:

```json
{
  "key": "auto",
  "label": "Авторабота",
  "type": "boolean",
  "required": false,
  "scope": "object",
  "objectKey": "automated",
  "default": false
}
```

Без `scope`, либо при `scope: "representation"`, свойство локально. Без `objectKey` ключ общего атрибута совпадает с `key`. Значение по умолчанию общего свойства записывается при создании нового объекта из палитры. Обычное размещение уже существующего объекта не переписывает его атрибуты. Если обязательных значений не хватает, редактор предлагает заполнить их перед размещением. Общие значения для нового объекта сохраняются вместе с его первым представлением одной транзакцией; у существующего объекта явно подтверждённые общие изменения сохраняются отдельно от раскладки. Эти привязки предназначены для свойств узлов; свойства связей локальны.

Смена отображения сохраняет объект, положение, размер, слой и локальную подпись. Совместимые свойства переносятся; прежние локальные значения хранятся в `profiles` под ключом `bindingId:typeId` для возвращения к прежнему отображению. Если связи перестают удовлетворять правилам, редактор открывает диалог сопоставления портов и типов связей. Удаление связи требует явного выбора; изменение не применяется до прохождения проверки. При удалении неиспользуемого подключения его неактивные профили также удаляются.

## История модели

Общие свойства имеют собственные ревизии. Ревизия диаграммы фиксирует представления, подключения нотаций и снимки общих объектов, участвовавших в этой версии. Просмотр/экспорт истории показывает снимки на момент сохранения. Восстановление диаграммы создаёт новую ревизию с актуальными общими объектами и не откатывает всю модель. Для отката общего объекта используется отдельная история в его редакторе.

Удаление объекта из дерева допускается после удаления всех его представлений и перемещения/удаления дочерних объектов. Снимки диаграмм остаются доступными для просмотра и экспорта. Восстановление такого снимка воссоздаёт удалённые объекты; данные объектов, сохранившихся в модели, остаются актуальными.

Необязательное поле `incarnation` в снимке объекта соответствует времени создания записи. Оно отличает восстановленный объект от удалённого с тем же ID: клиент принимает новые свойства даже при сбросе номера ревизии. Запросы изменения, удаления и восстановления объекта могут передавать это поле вместе с `revision` для защиты от устаревших операций.
