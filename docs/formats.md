# Документы и нотации

## Файл диаграммы

`.maket.json` содержит `{ "name": "Название", "document": { ... } }`. Импорт также принимает сам документ. Текущий формат диаграммы — **v2**; формат нотаций остаётся **v1**.

```json
{
  "schemaVersion": 2,
  "modelSpaceId": "space-id",
  "bindings": [{ "id": "binding-id", "versionId": null, "document": {} }],
  "objects": [
    {
      "id": "object-id",
      "parentId": null,
      "name": "Заказ",
      "description": "",
      "attributes": { "automated": true },
      "archived": false,
      "revision": 1
    }
  ],
  "nodes": [
    {
      "id": "representation-id",
      "objectId": "object-id",
      "bindingId": "binding-id",
      "typeId": "process",
      "position": { "x": 100, "y": 100 },
      "properties": {},
      "label": "Необязательная локальная подпись"
    }
  ],
  "edges": [
    {
      "id": "edge-id",
      "bindingId": "binding-id",
      "typeId": "flow",
      "source": "representation-id",
      "target": "another-representation-id",
      "sourcePort": "out",
      "targetPort": "in",
      "properties": { "label": "Далее" }
    }
  ]
}
```

Это иллюстрация структуры: `bindings[].document` должен содержать полную валидную нотацию, а оба конца связи — существовать. Рабочий файл получается экспортом из редактора. Исполняемые схемы: `src/lib/model.ts` и `src/lib/notation.ts`.

`objects` содержит снимки используемых объектов и их предков; `nodes` — независимые представления этих объектов. Несколько узлов могут иметь одинаковый `objectId`. `bindingId` фиксирует конкретный снимок нотации; одинаковые `typeId` в разных подключениях независимы. Поясняющая графическая связь использует `bindingId: null`, `typeId: "association"` и может соединять представления разных нотаций. Семантические связи нотации действуют внутри своего подключения.

Импорт в рабочей области принимает v1 и v2. При импорте v2 сервер создаёт новые идентификаторы объектов и подключений, переписывает ссылки и родителей, сохраняет повторные представления одного объекта. Нотации в файле автономны: `versionId` сбрасывается. Встроенный импорт редактора заменяет раскладку только в том же пространстве, с теми же подключениями и существующими объектами; для переноса между пространствами используйте «Импорт» в рабочей области.

Ограничения: 2 МБ на запрос/файл, 12 подключений нотаций, 5000 объектов в документе, 1000 представлений, 3000 связей. На нотацию: 50 типов узлов, 20 типов связей, 1000 правил. У объекта: имя до 100 символов, описание до 4000, до 100 атрибутов примитивных типов. Идентификаторы — латинские буквы, цифры, `_` и `-`, до 100 символов. Цвета — `#RRGGBB`, без внешних URL.

Прежний v1 `{schemaVersion:1, notation, nodes, edges}` поддерживается для импорта и исторических снимков. Существующие диаграммы переводятся в v2 при первом обращении к модели/библиотеке; каждому старому узлу соответствует отдельный объект со стабильным идентификатором. Прежняя история сохраняется в исходном виде. Совпадение имён не объединяет объекты.

## Файл нотации

`.notation.json` содержит документ нотации без обёртки. Обязательны:

- `schemaVersion: 1`, `id`, `version` в формате `major.minor.patch`, `name`;
- `nodeTypes`: уникальный `id`, `name`, `appearance`, `properties`, `ports`;
- `edgeTypes`: уникальный `id`, `name`, `appearance`, опциональные `properties`;
- `connectionRules`: `edgeType`, `source: {nodeType,port}`, `target: {nodeType,port}`, `allowSelfLoop`.

`appearance` узла: `shape` (`rectangle`, `rounded`, `diamond`, `ellipse`, `text`, `custom`), `width` (40–600), `height` (30–400), `fill`, `stroke`. Дополнительно: `strokeWidth` (0.5–12), `fontSize` (8–72), `textRotation` (−180…180 градусов), `textAlign` (`left`, `center`, `right`), `showAttributes` (по умолчанию включено). Для `custom` обязателен `shapeId` существующей формы.

Свойство: `key`, `label`, `type` (`string`, `number`, `boolean`), `required`, опциональный `default` соответствующего типа. Поле `title` отображается внутри узла, `label` — на связи. Остальные свойства узла также видны на фигуре; логические значения показаны как «Да»/«Нет». `visible: false` скрывает конкретное свойство на фигуре, сохраняя его в инспекторе. `showAttributes: false` скрывает весь блок атрибутов.

Порт: `id`, `direction` (`input` или `output`), опциональный `maxConnections`. Входы располагаются слева, выходы справа. Правила соединения могут ссылаться только на существующие типы и порты нужного направления.

Внешний вид связи: `line` (`solid`, `dashed`, `dotted`, `dash-dot`, `custom`), `targetMarker`, `color`. Дополнительно: `sourceMarker`, `width` (0.5–12), `markerSize` (8–40), `fontSize` (8–48), `routing` (`smoothstep`, `straight`, `bezier`). Маркеры обоих концов: `none`, `arrow`, `thin-arrow`, `thick-arrow`, `triangle`, `hollow-triangle`, `diamond`, `hollow-diamond`, `circle`. Для `custom` нужен `dashPattern`: 2–8 положительных чисел до 50, чередующих длины штрихов и промежутков в пикселях. Стандартные пунктирные шаблоны масштабируются с толщиной линии.

## Настройки отдельных элементов

Узел диаграммы может содержать `size: {width, height}` (40–2000 × 30–1600), целочисленный `layer` (−1000000…1000000), `label` (до 2000 символов) и `appearance` с переопределениями оформления. Связь также принимает `appearance`. Настройки экземпляра имеют приоритет над настройками типа, размеры — над размерами типа. Больший `layer` располагается выше. Команды перемещения по слоям нормализуют уровни, сохраняя взаимный порядок остальных элементов.

Двойной щелчок редактирует локальный `label` представления. Без локального `label` или `properties.title` строковое свойство `title` наследует имя объекта. Общие свойства редактируются отдельно через дерево или кнопку инспектора. «Сбросить локальную подпись» возвращает наследование общей подписи. Enter сохраняет текст, Shift+Enter добавляет строку, Escape отменяет изменение. Изменение размера доступно через рамку выбранного объекта и поля инспектора.

## Пользовательские формы

Необязательный массив `shapes` в нотации содержит до 50 форм. Пример формы и оформления типа:

```json
{
  "shapes": [
    {
      "id": "slanted-process",
      "name": "Скошенный процесс",
      "baseShape": "rectangle",
      "points": [
        { "x": 15, "y": 0 },
        { "x": 100, "y": 0 },
        { "x": 85, "y": 100 },
        { "x": 0, "y": 100 }
      ],
      "rounding": 8
    }
  ],
  "appearance": {
    "shape": "custom",
    "shapeId": "slanted-process",
    "width": 180,
    "height": 100,
    "fill": "#eef2ff",
    "stroke": "#6366f1"
  }
}
```

Фрагмент нужно разместить в полном документе: `shapes` на верхнем уровне, `appearance` внутри соответствующего `nodeTypes`. `baseShape` — `rectangle`, `rounded`, `diamond` или `ellipse`; `points` — 3–32 точки замкнутого контура с координатами 0–100 процентов; `rounding` — 0–45 процентов. Контур с нулевой площадью отклоняется. Конструктор позволяет менять базу, двигать точки, добавлять/удалять их и скруглять углы. Формы масштабируются с узлом и экспортируются вместе с нотацией. Произвольный SVG, HTML и исполняемый код не принимаются.

Поля оформления необязательны и совместимы с нотациями v1 и прежними файлами диаграмм v1. Прежние документы не получают новые поля при разборе. Новая версия нотации с формами применяется к новым диаграммам; уже созданные диаграммы продолжают использовать сохранённый снимок.

## Версии

- `schemaVersion` — версия файлового формата. Диаграммы сохраняются в v2; v1 поддерживается для импорта и истории. Нотации сохраняют формат v1. Неизвестные версии отклоняются.
- `bindings[].document.version` — версия языка моделирования. При редактировании должна увеличиваться. Все сохранённые версии остаются неизменяемыми.
- `Diagram.revision` — номер снимка диаграммы. Сервер принимает сохранение только при совпадении ожидаемого номера; иначе HTTP 409.

Существующая диаграмма хранит снимок нотации и ссылку на её версию (если создана из библиотеки нотаций). Замена нотации при сохранении запрещена. Импорт создаёт независимую диаграмму со встроенной нотацией. Восстановление создаёт новую ревизию; прежняя история не удаляется. Если неиспользуемая нотация уже удалена из библиотеки, её исторический снимок восстанавливается как автономное подключение с `versionId: null`.

## Область свойств и смена отображения

У свойства типа узла можно указать `scope: "object"` и `objectKey` для привязки к общему атрибуту. Например:

```json
{
  "key": "auto",
  "label": "Авторабота",
  "type": "boolean",
  "required": false,
  "scope": "object",
  "objectKey": "automated",
  "default": false
}
```

Без `scope`, либо при `scope: "representation"`, свойство локально. Без `objectKey` ключ общего атрибута совпадает с `key`. Значение по умолчанию общего свойства записывается при создании нового объекта из палитры. Обычное размещение уже существующего объекта не переписывает его атрибуты. Если обязательных значений не хватает, редактор предлагает заполнить их перед размещением. Общие значения для нового объекта сохраняются вместе с его первым представлением одной транзакцией; у существующего объекта явно подтверждённые общие изменения сохраняются отдельно от раскладки. Эти привязки предназначены для свойств узлов; свойства связей локальны.

Смена отображения сохраняет объект, положение, размер, слой и локальную подпись. Совместимые свойства переносятся; прежние локальные значения хранятся в `profiles` под ключом `bindingId:typeId` для возвращения к прежнему отображению. Если связи перестают удовлетворять правилам, редактор открывает диалог сопоставления портов и типов связей. Удаление связи требует явного выбора; изменение не применяется до прохождения проверки. При удалении неиспользуемого подключения его неактивные профили также удаляются.

## История модели

Общие свойства имеют собственные ревизии. Ревизия диаграммы фиксирует представления, подключения нотаций и снимки общих объектов, участвовавших в этой версии. Просмотр/экспорт истории показывает снимки на момент сохранения. Восстановление диаграммы создаёт новую ревизию с актуальными общими объектами и не откатывает всю модель. Для отката общего объекта используется отдельная история в его редакторе.

Удаление объекта из дерева допускается после удаления всех его представлений и перемещения/удаления дочерних объектов. Снимки диаграмм остаются доступными для просмотра и экспорта. Восстановление такого снимка воссоздаёт удалённые объекты; данные объектов, сохранившихся в модели, остаются актуальными.

Необязательное поле `incarnation` в снимке объекта соответствует времени создания записи. Оно отличает восстановленный объект от удалённого с тем же ID: клиент принимает новые свойства даже при сбросе номера ревизии. Запросы изменения, удаления и восстановления объекта могут передавать это поле вместе с `revision` для защиты от устаревших операций.

## Снимки связей в v2

Формат v2 расширен необязательным массивом `relations`. Старые файлы без него принимаются и обновляются при импорте/восстановлении. Каждая сохранённая стрелка получает `relationId`. Один ID может использоваться несколькими стрелками в разных диаграммах и нотациях. Направление и участники задаются общей связью, а `source`/`target` стрелки указывают на конкретные представления этих участников. Тип, порты, подпись и оформление остаются локальными. Поле `scope: "object"` в свойствах типа связи привязывает значение к общим атрибутам связи; `objectKey` переименовывает ключ так же, как для узлов.

`parentId` объекта или связи может ссылаться на объект либо другую связь; отсутствие `parentId` у старой связи означает корень. `sourceId` и `targetId` общей связи также принимают ID обоих видов сущностей. В `edges` поля `source`/`target` могут указывать на ID узла или другой стрелки. При подключении к стрелке обе точки равноправны: каждая может использоваться как источник или назначение. Имена `in` (слева) и `out` (справа) сохранены для совместимости файлов и не задают направление. Используется универсальное отображение (`bindingId: null`, `typeId: "association"`). Циклы вложенности и циклы зависимостей представлений стрелок запрещены. Снимок включает предков и участников общих связей, даже если их представления отсутствуют на канвасе. Импорт переназначает все эти ID согласованно; восстановление истории воссоздаёт удалённых участников перед их связями.

```json
{
  "relations": [
    {
      "id": "relation-1",
      "sourceId": "order",
      "targetId": "owner",
      "name": "Ответственность",
      "description": "",
      "attributes": { "role": "owner" },
      "archived": false,
      "revision": 1
    }
  ],
  "edges": [
    {
      "id": "arrow-1",
      "relationId": "relation-1",
      "bindingId": "notation-1",
      "typeId": "flow",
      "source": "order-view",
      "target": "owner-view",
      "sourcePort": "out",
      "targetPort": "in",
      "properties": { "label": "Локальная подпись" }
    }
  ]
}
```

Экспорт содержит снимки только используемых связей. Импорт выдаёт связям новые ID, переназначает участников и сохраняет повторное использование одной связи несколькими стрелками. История фиксирует общие свойства связей вместе с локальными стрелками. Восстановление создаёт отсутствующие связи и их участников, сохраняя исторические ID; общие данные уже существующих связей не откатываются.

Необязательное `copiedFrom: {"id": "original-id", "name": "Имя при копировании"}` у объектов и связей сохраняет происхождение. Запись не участвует в валидации ссылок модели и не требует присутствия оригинала в файле или базе. Копирование и импорт создают независимую запись с упоминанием непосредственного источника; размещение ещё одного представления сохраняет исходную запись.

## Свободные концы стрелок

Необязательные `detachedSource` и `detachedTarget` — координаты `{x, y}` в системе канваса. Они заменяют графическую привязку соответствующего конца. `source`/`target` и порты сохраняют последнюю привязку; её представление может уже отсутствовать. Семантические участники остаются в `relations.sourceId`/`targetId`, поэтому сохранение и экспорт включают их в снимок модели. Свободные концы не занимают порты и не создают зависимость от прежнего представления. При повторном соединении проверяются правила нотации и ограничения портов.

Перепривязка между представлениями одного участника сохраняет `relationId`. Смена участника создаёт новую связь с `copiedFrom` и сохраняет локальное оформление стрелки. Зависимые стрелки получают согласованные связи; другие представления исходной связи не меняются.

## Экспорт в draw.io

В редакторе и публичном вьюере откройте «Экспорт» → «draw.io». Скачанный `.drawio` — несжатый XML `mxfile` с `mxGraphModel`. Откройте его в draw.io / diagrams.net через «Файл → Открыть из → Устройство» либо импортируйте в существующий документ. Это редактируемые фигуры и соединения, а не единое изображение.

Переносятся положение (включая отрицательные координаты), размер, порядок фигур, подписи и видимые свойства, заливка, контур, шрифт, выравнивание, поворот текста, типы линий, маркеры и окончания соединений. Пользовательские формы передаются встроенными трафаретами mxGraph, без внешних картинок; повёрнутые подписи — прозрачными дочерними текстовыми элементами. Свободные концы стрелок сохраняются координатами, привязанные — ссылками на представления. draw.io пересчитывает маршруты линий своим движком; точные изгибы и переносы строк могут отличаться от maket.

Свойства находятся в XML-обёртке `object` и доступны через «Изменить данные» (`Edit Data`) выбранной фигуры или стрелки:

| Поле                                   | Содержимое                                                                                                                   |
| -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `maket_object_id`                      | ID общего объекта для фигуры                                                                                                 |
| `maket_relation_id`                    | ID общего отношения для стрелки                                                                                              |
| `maket_representation_id`              | Исходный ID конкретной фигуры или стрелки                                                                                    |
| `maket_type`                           | Тип представления с идентификатором подключения нотации                                                                      |
| `maket_name`, `maket_description`      | Общее имя и описание объекта                                                                                                 |
| `maket_source_id`, `maket_target_id`   | ID семантических участников отношения                                                                                        |
| `attribute_<ключ>`                     | Эффективные атрибуты для удобного просмотра в редакторе данных                                                               |
| `maket_attributes`, `maket_properties` | Эффективные атрибуты и свойства представления в JSON, включая типы чисел и boolean                                           |
| `maket_object`, `maket_relation`       | JSON-снимок соответствующей общей сущности, включая собственные/унаследованные атрибуты, ревизию и дополнительные метаданные |
| `maket_representation`                 | Исходные данные представления: локальные переопределения, положение, оформление и ссылки                                     |

ID ячеек draw.io имеют вид `node_<id представления>` и `edge_<id представления>`. Это позволяет нескольким фигурам одного объекта оставаться независимыми визуализациями без конфликтов ID. Общность сохраняется в `maket_object_id`; `maket_representation_id` не подменяется ID объекта.

Экспортируется открытая диаграмма и данные её представленных сущностей, а не весь каталог объектов области. Правила нотаций и синхронизация с maket в draw.io не исполняются. Для полного переноса и восстановления родных нотаций сохраняйте также `.maket.json`; импорт draw.io преобразует файл в отдельную редактируемую модель, как описано ниже.

## Импорт из draw.io

В рабочей области на вкладке «Диаграммы» нажмите «Импорт» и выберите `.drawio` или XML draw.io. Поддерживаются `mxfile` с обычными и сжатыми страницами (base64 → raw deflate → URL decoding) и отдельный `mxGraphModel`.

В корне выбранной рабочей области создаётся **новая папка с именем файла без расширения**. Все импортируемые объекты и связи помещаются в неё; каждая страница становится отдельной диаграммой в той же папке. Группы исходного файла учитываются при пересчёте абсолютных координат, но не создают дополнительную вложенность объектов. Для операции нужно право `create` без ограничения отдельными элементами. Весь файл сохраняется одной транзакцией: ошибка на любой странице откатывает создание папки, объектов, связей и диаграмм.

Фигуры получают редактируемые подписи, размеры, базовые контуры, цвет и доступные настройки текста; стрелки — участников, подписи и поддерживаемое оформление. HTML-подписи превращаются в обычный текст, код и обработчики не выполняются. При наличии метаданных maket восстанавливаются повторные представления общих объектов, собственные свойства, локальные значения, типизированные атрибуты, специальные связи и контуры трафаретов, созданных экспортом maket. Нативные `mxCell` без метаданных становятся отдельными объектами. Одинаковые `maket_object_id` на нескольких страницах одного файла используют один импортированный объект; при разных снимках общих свойств используется первый. Дополнительные свойства стрелок сохраняются как локальные атрибуты `drawio_property_<ключ>`.

Подписи сохраняют выравнивание сверху, по центру и снизу, расположение снаружи фигуры, отступы и смещение `mxGeometry.offset`. Сохраняются размер, жирное/обычное/тонкое начертание, курсив, подчёркивание и зачёркивание. Семейство шрифта используется, если оно установлено на устройстве; внешние шрифты не загружаются. Единое HTML-оформление подписи переносится в настройки текста; смешанное оформление отдельных фрагментов приводится к общему стилю с предупреждением, текст сохраняется полностью. Эти настройки сохраняются при повторном открытии, просмотре и экспорте.

Технические ID новой модели назначает сервер; ID из метаданных maket доступны в `copiedFrom`, а ID исходной ячейки — в атрибуте `drawio_id`, если для него остаётся место в лимите 100 атрибутов. При заполненном лимите пользовательские значения сохраняются без добавления служебного поля, с предупреждением. Повторный импорт не связывается с существующими объектами области и создаёт отдельную папку, даже если её имя совпадает. Свободные окончания сохраняются; если их семантический участник неизвестен, в папке создаётся объект «Свободный конец» без фигуры на канвасе.

Импорт использует встроенную нотацию документа «Импорт draw.io», а не восстанавливает каталог нотаций исходного приложения. Внешние изображения не загружаются, неподдерживаемые сложные трафареты заменяются базовыми фигурами с предупреждением. Поворот контура фигуры и произвольные путевые точки не входят в модель maket: маршруты пересчитываются движком приложения. Для больших фигур страница пропорционально уменьшается до допустимых размеров; минимальные размеры фигур ограничены редактором. Предупреждения и ссылка на папку показываются после успешного импорта.

Ограничения: до 20 страниц, до 1000 фигур и 3000 стрелок на странице, до 50 вариантов типов фигур и 30 свойств каждого типа. Файл, общий объём распакованных данных и итоговый JSON ограничены 2 МБ. DTD, XML-сущности, циклы вложенности и связей между стрелками, некорректные документы отклоняются до сохранения. Неизвестные поля не позволяют назначить владельца или права доступа; сервер заново проверяет схему и правила модели.

## Геометрия импортированных стрелок

Поля представления связи `sourceAnchor` и `targetAnchor` задают точку привязки как долю ширины/высоты фигуры. Это сохраняет соединение при перемещении и изменении размеров. `waypoints` хранит до 256 промежуточных точек в координатах диаграммы; пустой массив означает прямой ручной маршрут, отсутствие поля — автоматическую маршрутизацию. `labelPosition` задаёт долю длины маршрута `along`, нормальное смещение `normal`, дополнительный `offset` и признак `relative`. Все поля необязательны и совместимы с существующими JSON v1/v2 без миграции базы.

Импорт draw.io переводит свободные концы и контрольные точки из координат родительской группы в координаты диаграммы и применяет масштаб страницы один раз. Для абсолютных фигур `mxGeometry.offset` не смещает саму фигуру; для относительных учитывается. Привязки `entryX/Y`, `exitX/Y` и сохранённые точки маршрута используются в редакторе, превью, публичном вьюере и экспорте. Специальные автоматические маршрутизаторы draw.io без сохранённых точек не воспроизводятся побайтно: маршрут строится движком maket. Повторное экспортирование сохраняет явную геометрию в XML.
