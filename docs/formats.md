# Документы и нотации

## Файл диаграммы

`.maket.json` содержит `{ "name": "Название", "document": { ... } }`. Импорт также принимает сам документ. Формат документа:

```json
{
  "schemaVersion": 1,
  "notation": {
    "schemaVersion": 1,
    "id": "...",
    "version": "1.0.0",
    "name": "...",
    "nodeTypes": [],
    "edgeTypes": [],
    "connectionRules": []
  },
  "nodes": [
    {
      "id": "n1",
      "typeId": "process",
      "position": { "x": 100, "y": 100 },
      "properties": { "title": "Заказ" }
    }
  ],
  "edges": [
    {
      "id": "e1",
      "typeId": "flow",
      "source": "n1",
      "target": "n2",
      "sourcePort": "out",
      "targetPort": "in",
      "properties": { "label": "Перейти" }
    }
  ]
}
```

Этот фрагмент иллюстрирует структуру, не является валидной диаграммой: определение нотации сокращено, `n2` отсутствует. Рабочий пример можно получить экспортом готовой блок-схемы в приложении. Авторитетная исполняемая схема — `src/lib/notation.ts`.

Ограничения: 2 МБ на запрос/файл, 1000 узлов, 3000 связей, 50 типов узлов, 20 типов связей, 1000 правил. Идентификаторы — латинские буквы, цифры, `_` и `-`, до 100 символов. Цвета — `#RRGGBB`, без внешних URL.

## Файл нотации

`.notation.json` содержит документ нотации без обёртки. Обязательны:

- `schemaVersion: 1`, `id`, `version` в формате `major.minor.patch`, `name`;
- `nodeTypes`: уникальный `id`, `name`, `appearance`, `properties`, `ports`;
- `edgeTypes`: уникальный `id`, `name`, `appearance`, опциональные `properties`;
- `connectionRules`: `edgeType`, `source: {nodeType,port}`, `target: {nodeType,port}`, `allowSelfLoop`.

`appearance` узла: `shape` (`rectangle`, `rounded`, `diamond`, `ellipse`, `text`, `custom`), `width` (40–600), `height` (30–400), `fill`, `stroke`. Дополнительно: `strokeWidth` (0.5–12), `fontSize` (8–72), `textRotation` (−180…180 градусов), `textAlign` (`left`, `center`, `right`), `showAttributes` (по умолчанию включено). Для `custom` обязателен `shapeId` существующей формы.

Свойство: `key`, `label`, `type` (`string`, `number`, `boolean`), `required`, опциональный `default` соответствующего типа. Поле `title` отображается внутри узла, `label` — на связи. Остальные свойства узла также видны на фигуре; логические значения показаны как «Да»/«Нет». `visible: false` скрывает конкретное свойство на фигуре, сохраняя его в инспекторе. `showAttributes: false` скрывает весь блок атрибутов.

Порт: `id`, `direction` (`input` или `output`), опциональный `maxConnections`. Входы располагаются слева, выходы справа. Правила соединения могут ссылаться только на существующие типы и порты нужного направления.

Внешний вид связи: `line` (`solid`, `dashed`, `dotted`, `dash-dot`, `custom`), `targetMarker`, `color`. Дополнительно: `sourceMarker`, `width` (0.5–12), `markerSize` (8–40), `fontSize` (8–48), `routing` (`smoothstep`, `straight`, `bezier`). Маркеры обоих концов: `none`, `arrow`, `thin-arrow`, `thick-arrow`, `triangle`, `hollow-triangle`, `diamond`, `hollow-diamond`, `circle`. Для `custom` нужен `dashPattern`: 2–8 положительных чисел до 50, чередующих длины штрихов и промежутков в пикселях. Стандартные пунктирные шаблоны масштабируются с толщиной линии.

## Настройки отдельных элементов

Узел диаграммы может содержать `size: {width, height}` (40–2000 × 30–1600), целочисленный `layer` (−1000000…1000000), `label` (до 2000 символов) и `appearance` с переопределениями оформления. Связь также принимает `appearance`. Настройки экземпляра имеют приоритет над настройками типа, размеры — над размерами типа. Больший `layer` располагается выше. Команды перемещения по слоям нормализуют уровни, сохраняя взаимный порядок остальных элементов.

Двойной щелчок редактирует `properties.title`, если в типе объявлено строковое свойство `title`; иначе используется `label`. Enter сохраняет текст, Shift+Enter добавляет строку, Escape отменяет изменение. Изменение размера доступно через рамку выбранного объекта и поля инспектора.

## Пользовательские формы

Необязательный массив `shapes` в нотации содержит до 50 форм. Пример формы и оформления типа:

```json
{
  "shapes": [
    {
      "id": "slanted-process",
      "name": "Скошенный процесс",
      "baseShape": "rectangle",
      "points": [
        { "x": 15, "y": 0 },
        { "x": 100, "y": 0 },
        { "x": 85, "y": 100 },
        { "x": 0, "y": 100 }
      ],
      "rounding": 8
    }
  ],
  "appearance": {
    "shape": "custom",
    "shapeId": "slanted-process",
    "width": 180,
    "height": 100,
    "fill": "#eef2ff",
    "stroke": "#6366f1"
  }
}
```

Фрагмент нужно разместить в полном документе: `shapes` на верхнем уровне, `appearance` внутри соответствующего `nodeTypes`. `baseShape` — `rectangle`, `rounded`, `diamond` или `ellipse`; `points` — 3–32 точки замкнутого контура с координатами 0–100 процентов; `rounding` — 0–45 процентов. Контур с нулевой площадью отклоняется. Конструктор позволяет менять базу, двигать точки, добавлять/удалять их и скруглять углы. Формы масштабируются с узлом и экспортируются вместе с нотацией. Произвольный SVG, HTML и исполняемый код не принимаются.

Новые поля необязательны и совместимы с `schemaVersion: 1`. Прежние документы не получают новые поля при разборе. Новая версия нотации с формами применяется к новым диаграммам; уже созданные диаграммы продолжают использовать сохранённый снимок.

## Версии

- `schemaVersion` — версия файлового формата. Сейчас поддерживается только 1; другие версии явно отклоняются. При появлении версии 2 понадобится отдельная миграция документа и тесты совместимости.
- `notation.version` — версия языка моделирования. При редактировании должна увеличиваться. Все сохранённые версии остаются неизменяемыми.
- `Diagram.revision` — номер снимка диаграммы. Сервер принимает сохранение только при совпадении ожидаемого номера; иначе HTTP 409.

Существующая диаграмма хранит снимок нотации и ссылку на её версию (если создана из библиотеки нотаций). Замена нотации при сохранении запрещена. Импорт создаёт независимую диаграмму со встроенной нотацией. Восстановление создаёт новую ревизию; прежняя история не удаляется.
