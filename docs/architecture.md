# Архитектура

## Реализованный вертикальный срез

Next.js App Router обслуживает страницы и API. `src/app/api/[...path]/route.ts` содержит операции учётных записей и принадлежащих пользователю ресурсов. Сервер проверяет сессию, владельца, входную схему и правила диаграмм. Операции модели и диаграмм вынесены в `src/lib/model-service.ts`; проверка формата и проекция для React Flow — в `src/lib/model.ts`.

`src/lib/notation.ts` — декларативные схемы, семантический валидатор, значения по умолчанию и встроенная блок-схема. Код или HTML из пользовательских файлов не выполняются. React Flow рисует пользовательские узлы через безопасные SVG-примитивы и текстовые подписи React.

`src/lib/appearance.ts` содержит совместимые необязательные расширения оформления, модель слоёв и числовые контуры пользовательских форм. `NodeShape` используется канвасом и предпросмотрами. У экземпляров узлов и связей есть собственные настройки; снимок нотации остаётся неизменным. Конструктор форм ограничивает координаты и число точек, SVG строится из чисел внутри приложения.

Редактор сохраняет стабильные объекты React Flow для неизменённых узлов. Подтверждение автосохранения обновляет только номер ревизии и отметку сохранённого документа. Подгонка камеры выполняется при изменении состава узлов, а не при перемещении или сохранении. Перемещение, изменение размеров и ввод текста приостанавливают автосохранение и образуют один шаг отмены. Редактор нотации использует диалог фиксированной высоты, который остаётся открытым при изменении полей. Тема распространяется на корневой документ, канвас, миникарту, контролы и диалоги.

Данные — PostgreSQL; Prisma Client с `engineType = client` и официальным pg adapter. Схема БД, миграции и индекс владельца/времени находятся в `prisma/`. Диаграммы и версии нотаций — JSONB. Объекты, их ревизии, дерево, пространства и индексы использования представлены отдельными таблицами. Сохранение документа и создание ревизии выполняются в одной транзакции. Номер ревизии защищает от потери изменений между вкладками.

Сессии живут 7 дней. Подтверждение почты — 24 часа, восстановление — 1 час. В БД хранятся хеши одноразовых токенов и токенов сессий. Токен восстановления потребляется атомарно. Пароли хешируются scrypt с индивидуальной случайной солью. Изменение/восстановление пароля инвалидирует старые сессии.

Изменяющие запросы проверяют Origin и Sec-Fetch-Site; JSON-операции требуют соответствующий Content-Type. Сессионная cookie — HttpOnly, SameSite=Lax; Secure включается для HTTPS APP_URL. Формы входа/восстановления имеют ограничения попыток в БД. Это базовая защита; перед открытым масштабным запуском нужны ограничения на уровне ingress по доверенному IP, очередь почты и эксплуатационный мониторинг.

## Подготовленная среда

В текущей машине: Node.js 24, PostgreSQL 17 в контейнере `maket-postgres`, зависимости и сгенерированный Prisma Client. Node.js 22 используется как базовая версия проекта и в CI. Процессы не считаются частью снимка среды и должны запускаться заново.

## Продолжение разработки

1. Полный визуальный конструктор свойств, портов и правил (сейчас расширенная настройка — через JSON).
2. Пагинация библиотеки, отдельное API метаданных вместо полной загрузки документов, виртуализация больших списков.
3. Очередь доставки писем, мониторинг сбоев, автоматическая очистка просроченных сессий, токенов и rate-limit записей.
4. Google OAuth с привязкой аккаунтов и настройкой разрешённых callback URL.
5. PNG/SVG-экспорт, улучшенное расположение портов и расширенные ограничения нотаций.
6. Отдельная процедура перехода диаграммы на новую версию нотации с предпросмотром изменений.
7. Командные пространства и совместное редактирование — отдельный этап с моделью доступа и протоколом синхронизации.

Тесты проверяют правила нотаций, совместимость прежних документов, слои и оформление, полный цикл локальной почтовой авторизации, владение ресурсами, неизменяемость нотаций, конфликты ревизий, восстановление, импорт и браузерные сценарии редактора. Дополнительные браузерные проверки покрывают размеры и отмену, текст, атрибуты, слои, линии и маркеры, тёмную тему, сохранение после жеста, стабильность камеры/DOM и создание пользовательской формы. Production-доставка через внешний почтовый сервис требует отдельной проверки после настройки интеграции.

## Пространство объектов

Первая реализация создаёт одно личное `ModelSpace` на пользователя. `ModelObject` не имеет ссылки на нотацию; хранит общие имя, описание, атрибуты, родителя, архивный статус и номер ревизии. Составной внешний ключ `(spaceId, parentId)` удерживает вложенность внутри пространства. Перемещение в дереве проверяет циклы под блокировкой строки пространства, поэтому параллельные перемещения не могут создать цикл.

Представления хранятся в документе v2 и ссылаются на `objectId`. Геометрия, подпись, оформление и профиль нотации локальны представлению. Создание объекта и первого представления из палитры выполняется одной транзакцией. Удаление представления/диаграммы не удаляет объект; архивирование сохраняет существующие представления и детей, запрещая новые размещения. Обычное дублирование диаграммы разделяет общие объекты с оригиналом; импорт создаёт независимые объекты.

`DiagramObjectUsage` индексирует число представлений объекта в диаграмме, `DiagramNotation` — закреплённые версии нотаций. Индексы, документ и историческая ревизия обновляются одной транзакцией. Проверки принадлежности защищают ссылки на чужие объекты и нотации. Изменения объектов и диаграмм требуют ожидаемого номера ревизии, конфликт возвращает HTTP 409.

API: `GET /api/model`; `POST /api/objects`; `GET/PATCH /api/objects/:id`; `GET /api/objects/:id/usages`; `GET /api/objects/:id/revisions`; `POST /api/objects/:id/restore`. Диаграммы: `POST /api/diagrams/:id/representations`, `POST /api/diagrams/:id/notations`, `GET /api/diagrams/:id/history?number=N`, прежние операции создания/сохранения/восстановления/копирования/удаления.

Редактор получает общие объекты отдельно от раскладки, проверяет обновления каждые 5 секунд в видимой вкладке и при фокусе. При обновлении сохраняет ссылки неизменённых объектов, не заменяет граф и не сбрасывает камеру. Это периодическая синхронизация личной модели; совместное редактирование и мгновенные события остаются отдельным этапом. Отмена на канвасе меняет только представления; общие изменения восстанавливаются через историю объекта.

Нотации остаются декларативными скинами, подключёнными по фиксированной версии. Обычные связи подчиняются правилам собственного подключения. Универсальные поясняющие связи графические; отдельная семантическая модель отношений между объектами пока не вводится. Командные пространства, множественные родители, виртуализация больших деревьев и автоматический переход нотаций на новые версии требуют дальнейшего этапа.

Расширенные проверки покрывают миграцию v1, создание на чистой БД, циклы при параллельных перемещениях, откат атомарного размещения при конфликте, владение объектами, общие свойства, повторные представления, несколько закреплённых нотаций, исторические снимки, восстановление без отката модели, архивирование и импорт с переписыванием ссылок.
