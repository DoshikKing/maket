# Аудит безопасности · 26 октября 2026

## Объём и метод

Проверены серверный API, сессии и восстановление пароля, приглашения, роли и ограничения элементов, рабочие области, история и блокировки, публичные ссылки, импорт нотаций, SVG/PDF-экспорт, SQL, Docker и пример Nginx. Проведены ручной анализ кода, проверка npm advisory database и воспроизводимые API/браузерные проверки с независимыми аккаунтами. Рабочий сервер пользователя и его фактическая конфигурация Nginx/ОС не сканировались.

Уровни ниже — оценка влияния и предусловий в этом приложении. Критичность advisory зависимости не означает, что соответствующий способ атаки воспроизведён в Maket.

## Найдено и исправлено

| Проблема                                                                        | Уровень | Исправление и проверка                                                                                                                                                                                                                                                                                                                                                                                                 |
| ------------------------------------------------------------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Повышение прав через кастомные роли                                             | Высокий | Обладатель только `members` мог назначить себе `admin`; обладатель `roles` мог расширить собственную роль. Теперь назначаемая, изменяемая и удаляемая роль проверяется на подмножество прав действующего пользователя, включая ограничения элементов. Проверяется и предыдущая роль участника: нельзя понизить или удалить более привилегированного участника. Владелец сохраняет полный доступ.                       |
| Раскрытие секретных публичных ссылок                                            | Высокий | `GET /objects/:id/share` и `GET /diagrams/:id/share` не требовали `share`. Полные строки диаграмм также включали `shareToken` в обычные ответы чтения и записи. Теперь получение ссылки требует `share`, а токен удаляется из общих ответов API, включая список и историю. Пользовательский атрибут с названием `shareToken` сохраняется.                                                                              |
| Обход ограничений и блокировок через историю                                    | Средний | Проверки учитывали текущий запрос, но не восстановленные `parentId`, `sourceId`, `targetId`. Теперь участники и родители берутся из серверного снимка истории до выполнения операции и входят в проверку прав/блокировок. Восстановление удалённых объектов и связей, включая невидимых предков из снимка диаграммы, требует `create`.                                                                                 |
| Неявное удаление переходов вместе с диаграммой                                  | Средний | Проверялась диаграмма, но не автоматически удаляемые связи декомпозиции/углубления. Теперь эти связи и затронутые элементы включаются в проверку `delete` и действующих блокировок.                                                                                                                                                                                                                                    |
| Старые reset-ссылки после смены пароля                                          | Средний | Смена пароля в настройках отзывала сессии, но оставляла ранее выданные токены восстановления. Теперь токены восстановления удаляются в той же транзакции.                                                                                                                                                                                                                                                              |
| Гонка входа и смены/сброса пароля                                               | Средний | Проверка старого пароля могла завершиться до сброса, а выдача сессии — после отзыва сессий. Теперь выдача сессии блокирует строку пользователя и сверяет актуальный хеш. Изменение пароля также проверяет предыдущий хеш, чтобы устаревший запрос не перезаписал новый пароль.                                                                                                                                         |
| Перебор с переключением email и различимое время проверки неизвестного аккаунта | Средний | Вход ограничивался только email, а неизвестный аккаунт запускал два scrypt вместо одного. Добавлен лимит на адрес: 60 запросов входа и 30 запросов восстановления за 15 минут, дополнительно к существующим ограничениям email. Для отсутствующего пользователя выполняется один scrypt, как для существующего. Это уменьшает различие времени проверки; абсолютная неразличимость всех сетевых ответов не заявляется. |
| Чрезмерная вложенность JSON                                                     | Средний | Ограничения размера тела недостаточно для защиты рекурсивного обхода произвольного JSON до валидации. Добавлен итеративный контроль глубины: не более 32 уровней. Переполнение отклоняется с HTTP 400; лимит тела 2 МБ сохранён.                                                                                                                                                                                       |

Дополнительно добавлены CSP-директивы `object-src`, `base-uri`, `frame-ancestors`, `form-action` и запрет доступа к камере, микрофону и геолокации. Это дополнительная защита в браузере; политика не объявляется строгой script CSP с nonce.

PDF-экспорт Maket использует `addImage` с растровым изображением собственного SVG, а не `jsPDF.html()` с произвольным HTML. Прямое использование уязвимых режимов DOMPurify в коде приложения не обнаружено; транзитивная зависимость всё равно обновлена.

После обновления `npm audit` и `npm audit --omit=dev` сообщают **0 уязвимостей**. Это состояние базы advisory на дату проверки, а не гарантия отсутствия неизвестных уязвимостей.

## Проверки

- Модульные тесты: 80 успешно, включая запрет повышения прав и ограничение глубины JSON.
- API/браузерные тесты: 18 успешно (7 security и 11 регрессионных). Отдельный security-набор проверяет изоляцию рабочих областей, права публикации и отсутствие токенов в общих ответах, отзыв/ротацию публичных ссылок, управление ролями, историю, блокировки, неявное удаление переходов, CSRF, размер и глубину тела, лимит входа, экранирование HTML и PDF-экспорт.
- Проверка гонки паролей удерживает строку пользователя в PostgreSQL, дожидается заблокированной выдачи сессии, меняет хеш и убеждается, что вход со старым паролем отклонён.
- Регрессия основных сценариев и конкурентного редактирования: `collaboration.spec.ts` и `workflow.spec.ts`.
- Проверки типов, форматирования и production-сборка для `APP_URL=/maket`. Дополнительно запущен production standalone: проверены health, защитные заголовки, cookie `HttpOnly`/`Secure`/`SameSite`, создание объекта после входа и анонимная публичная ссылка с подпутём `/maket`.

Команды повторной проверки:

```bash
npm ci
npm audit
npm run typecheck
npm test
PLAYWRIGHT_CHROMIUM_EXECUTABLE=/usr/bin/chromium npm run test:e2e -- tests/e2e/security.spec.ts tests/e2e/collaboration.spec.ts tests/e2e/workflow.spec.ts
APP_URL=/maket BUILD_STANDALONE=1 npm run build
```

E2E требует тестовой PostgreSQL и запускает dev-сервер; используйте отдельную тестовую среду. Production-сборку запускайте после остановки dev-сервера, так как оба используют `.next`.

## Развёртывание и оставшиеся условия

1. Пересоберите production-образ: `docker compose --env-file .env.production -f compose.prod.yaml up -d --build --wait`. Дополнительных миграций БД для этих исправлений нет.
2. Если ранее ограниченные участники имели доступ к пространству с включёнными публичными ссылками, рассмотрите ротацию этих ссылок кнопкой «Сгенерировать новую». Ранее скопированную ссылку исправление прав не отзывает. Автоматически существующие ссылки не изменяются.
3. Лимиты адреса и HTTPS-cookie опираются на заголовки доверенного reverse proxy. Пример `deploy/nginx/maket.conf` перезаписывает `X-Forwarded-For`, `X-Forwarded-Host`, `X-Forwarded-Proto`; backend должен оставаться на loopback или в закрытой сети. Прямой публичный доступ к backend с произвольными forwarded-заголовками не является поддерживаемой схемой развёртывания.
4. `elementIds` согласно текущему интерфейсу ограничивает изменяемые элементы, а не видимость данных пространства. Участники с `read` видят пространство целиком. Для данных, которые нельзя показывать другим участникам, используйте отдельное пространство.
5. Публичные ссылки дают доступ любому их обладателю, включая актуальные унаследованные свойства и необходимое дерево диаграммы. Это назначение функции; в ссылку не включается пароль или сессионный токен.
6. Регистрация по общему коду подтверждает владение кодом, но не почтовым ящиком. При выдаче доступа к зарегистрированному аккаунту администратору нужно сверять личность получателя; код и логи контейнера доступны только доверенным лицам.
7. Аудит npm не проверяет пакеты ОС образа и фактические правила firewall/TLS на сервере. Внешний пентест, сканирование ОС/образа и эксплуатационная проверка серверной инфраструктуры в этот аудит не входят.
